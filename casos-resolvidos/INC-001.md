# INC-001 — Usuário sem acesso após o almoço

**Data:** Agosto 2026  
**Analista:** Matheus Grun  
**Prioridade:** Alta  
**Status:** ✅ Resolvido  
**Tempo de resolução:** 12 minutos

---

## Relato do usuário

*"Estava funcionando normalmente, saí para o almoço e quando voltei não consigo acessar nada. Nem internet, nem os sistemas internos da empresa."*

---

## Diagnóstico

| Passo | Comando | Resultado |
|-------|---------|-----------|
| 1 | `ipconfig` | IP: 169.254.45.23 — DHCP falhou |
| 2 | Verificação física | Cabo conectado — ok |
| 3 | `ipconfig /release` | IP liberado |
| 4 | `ipconfig /renew` | Novo IP obtido: 192.168.1.105 |
| 5 | `ping gateway` | Resposta recebida — rede local ok |
| 6 | `ping 8.8.8.8` | Resposta recebida — internet ok |

---

## Solução aplicada

IP inválido — 169.254.x.x — causado por falha temporária no DHCP. Executado `ipconfig /release` seguido de `ipconfig /renew` para forçar a obtenção de novo endereço IP válido.

Usuário confirmou acesso normalizado a todos os sistemas.

---

## Causa raiz

Falha temporária no servidor DHCP durante o período de almoço — computador não conseguiu renovar o IP e recebeu endereço APIPA automaticamente.

---

## Lição aprendida

IP 169.254.x.x é sempre sinal de falha no DHCP. Antes de rodar os comandos verificar fisicamente o cabo — se estiver desconectado o `ipconfig /renew` não vai funcionar.
